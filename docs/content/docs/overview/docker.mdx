# Docker Deployment

## Use the published image

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## Production CORS proxy

The main image is a static frontend, so browser requests to an AI or WebDAV URL require that service to allow your site's origin. The repository includes `canvas-proxy`; the Compose setup routes same-origin `/proxy/` requests to it and enables it with `CANVAS_PROXY_URL=/proxy`:

```bash
docker compose up -d --build
```

The proxy forwards `/proxy/https://target.example/...` to the target. Keep it behind your own HTTPS site and do not expose it as a public standalone service. API keys remain in the browser and are forwarded with each request.

The main application container only serves the static frontend. Canvases, My Assets, generation history, and API keys are stored in the browser by default; the proxy does not persist application data.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
